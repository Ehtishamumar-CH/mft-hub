| D13 | **Partner onboarding via `config/partners.json`** (id, name, SSH public keys, optional source IPs) → CDK creates per-partner secret + S3 home prefixes. Onboarding = PR + `cdk deploy`. Demo partners `ACMEBANK`, `GLOBEX`. | IaC onboarding; public keys are safe to commit. |

| D19 | **Bucket hardening:** Block Public Access, BucketOwnerEnforced, TLS-only policy, versioning, server access logs to a dedicated log bucket. **Lifecycle:** `rejected/` expires 30d; processed → Standard-IA 30d → Glacier 180d; abort incomplete multipart uploads after 7d. | Baseline compliance controls + storage cost control. |
| D20 | **SFTP logical home:** `/inbound` → landing `inbound/<partner>/` (write); `/processed` → processed `<partner>/` (read-only); `/rejected` → quarantine `rejected/<partner>/` (read-only). Enforced by per-partner IAM session policy. | Partner jail + least privilege. |
| D21 | **Observability:** Powertools for AWS Lambda (Python) — structured JSON logs, correlation IDs, custom metrics `FilesValidated` / `FilesRejected{reason}`; X-Ray tracing; Transfer Family CloudWatch logging. | Diagnosable in production. |

| D26 | **Budget via CDK custom resource.** `MftCoreStack` manages the $10/month account budget with an `AwsCustomResource` that calls the Budgets API (`us-east-1` endpoint): ACTUAL 50/80/100 %, FORECASTED 100 %, all to the alert topic. The budget name carries a config hash, so a change creates the new budget before the old one is deleted. _(2026-11-11, chosen by user.)_ | CloudFormation has no `AWS::Budgets::Budget` type in `eu-central-2` or `eu-north-1`, and the region SCP denies CloudFormation in `us-east-1`. The Budgets API itself is allowed. Keeps the budget in IaC and removes it on destroy. |
| D27 | **IdP builds the session policy; secrets hold only partner data.** Each `mft/partners/<ID>` secret holds `partnerId`, `name`, `enabled`, `publicKeys`, `sourceIps`. The IdP Lambda derives the role ARN, the D20 logical home directories and a concrete per-partner session policy from environment variables. _(2026-11-11; replaces the earlier default that stored role and mappings in the secret.)_ | Policy variables are not supported with LOGICAL home directories, so the policy must be concrete per partner. Building it in code keeps it unit-tested (2048-char limit) and lets a partner be disabled by editing one secret field. |
| D28 | **Partner access role is the ceiling, the session policy the floor.** One role (in `MftCoreStack`) trusted by `transfer.amazonaws.com` with `aws:SourceAccount` + `aws:SourceArn` `user/*`. It allows `ListBucket` on the three buckets, `Put/Get/AbortMultipartUpload` on `inbound/*`, `Get/GetVersion` on processed and `rejected/*`, and KMS only `via s3`. No delete permissions. The session policy repeats the KMS statement, because effective access is role ∩ session policy. | Least privilege per partner with a single role (D4, D20). |
| D29 | **Server hardening:** `SftpAuthenticationMethods: PUBLIC_KEY` (the IdP also denies any password), security policy `TransferSecurityPolicy-2025-03`, structured JSON logs to a log group in `MftCoreStack` (retained, 1-year retention) so logs survive SFTP teardowns. The IdP Lambda has its own role (no AWS managed policies), may be invoked only by this server's ARN, and never logs the raw event. | Defence in depth, audit trail beyond the ephemeral stack. |
| D30 | **Idempotency key is the object version, not the eTag.** Refines D18 and D12: the record key is `partnerId` + `sk` = `<transferTs>#<sourceKey>#<versionId>`, where `transferTs` is the version's `LastModified`. The `RECEIVED` record is a conditional put; a duplicate event for a version in a final state is skipped. Steps run in the order record, validate, copy, delete from landing, final status, so a crash leaves `RECEIVED` and the retry finishes the job. The eTag is stored but not part of the key. _(2026-11-11.)_ | The same content uploaded again has the same eTag but is a new transfer and must be processed. The landing bucket is versioned, so the version ID is unique per upload and identical across duplicate events. Writing the final status last makes every step safe to repeat. |
| D31 | **Pipeline wiring specifics.** S3 to EventBridge via the native `NotificationConfiguration.EventBridgeConfiguration` (no CDK custom resource). Rule: `aws.s3` / `Object Created` / landing bucket / key prefix `inbound/`. Both queues use the project CMK and are TLS-only. Processing queue visibility 30 min (6x the 5-min Lambda timeout), DLQ retention 14 days, and the DLQ also catches EventBridge delivery failures. Batch size 10, max concurrency 2. Processor has its own role: delete only in landing `inbound/*`, put and tag only in processed `*` and quarantine `rejected/*`, KMS only via S3 and DynamoDB. Table is deletion-protected and retained. Folder markers (`.../`) are ignored; keys outside `inbound/<PARTNER>/<file>` are rejected as `INVALID_PATH`. | Fewer moving parts and nag findings; AWS guidance for SQS sources; the audit table outlives any stack mistake. |
| D32 | **Alarms (refines D14).** Four alarms to the alert topic, each with ALARM and OK actions and missing data treated as not breaching: DLQ visible messages ≥ 1; processor `Errors` ≥ 1 in 5 min; processing queue oldest message > 1 h; rejected rate > 50 % in 1 h once at least 3 files arrived (metric math on `FilesValidated` / `FilesRejected`). The budget alerts stay in D26. CloudWatch gets `sns:Publish` on the topic and `kms:GenerateDataKey*` + `kms:Decrypt` on the key, both scoped by `aws:SourceAccount` and `aws:SourceArn` `alarm:*`. Per-file failures are caught and retried, so they do not raise Lambda `Errors`; the DLQ alarm is the signal for those. _(2026-11-11.)_ | Signals an operator acts on, with no noise when idle; the confused-deputy conditions follow the CloudWatch SNS guide. |
| D33 | **Powertools via the AWS-managed layer (refines D21).** Processor uses layer `AWSLambdaPowertoolsPythonV3-python312-arm64` version 40 (Powertools 3.37.0, same as the test pin), active X-Ray tracing, JSON logs with the EventBridge event ID as correlation ID, and EMF metrics in namespace `MftHub`: `FilesValidated`, `FilesRejected`, `FilesRejected{reason}`, `ProcessingFailures`. Duplicates are not counted. The log line records `keyDecoded`; live data showed EventBridge sends raw (not URL-encoded) keys. The IdP Lambda keeps its stdlib JSON logging for now. _(2026-11-11.)_ | No packaging step or Docker; the version is pinned and matches CI. |
| D34 | **Teardown in three opt-in levels (`scripts/teardown.sh`).** Default: destroy `MftSftpStack` only (D9). `--all`: write a manifest of the core stack's retained resources (KMS key, 4 buckets, audit table, log groups) to gitignored `.teardown/`, turn off termination protection and destroy `MftCoreStack`; the retained resources stay. `--purge` (with `--all`, or with a manifest): delete every object version and the buckets (access-log bucket last), the table (after turning off deletion protection), the log groups, and schedule the key for deletion in 7 days. `--all` and `--purge` need a typed confirmation; `--dry-run` prints every command. The CDK bootstrap stack is never touched. _(2026-11-11.)_ | Routine teardown is one safe command; destroying data needs two deliberate steps. Retained resources are found from a manifest, not by tag: CloudFormation does not tag the key, table or queues with the stack name, and the bootstrap resources share the project tag. |

## Defaults (assumed unless overridden)

- npm as package manager; MIT license; README with architecture diagram (Mermaid).
- Partner secrets named `mft/partners/<PARTNERID>`, containing public keys, role ARN, home-directory mappings, optional source-IP allowlist (checked by IdP Lambda).
- Lambdas on arm64; processing Lambda 512 MB / 5 min timeout (streams the object for SHA-256); IdP Lambda 128 MB / 10 s.
- AWS Budget: $10/month, alerts at 50% / 80% / 100% forecast to the SNS topic.
- Phase 1 specifics: the access-log bucket is **SSE-S3** (S3 cannot deliver server access logs to SSE-KMS buckets) and expires logs after 90 days. Noncurrent versions expire after 7 days (landing, quarantine, logs) or 30 days (processed). All buckets and the KMS key are `RETAIN`.
- The alert topic is SSE-KMS with the project CMK, so the key policy grants `budgets.amazonaws.com` `kms:GenerateDataKey*` + `kms:Decrypt`. Both the topic and key statements are scoped by `aws:SourceAccount` + `aws:SourceArn` (AWS Budgets SNS guide). Phase 4 adds the same for `cloudwatch.amazonaws.com` alarms (D32).
- Resource tags: `Project=mft-hub`, `Owner=<user>`, `Environment=demo`.
